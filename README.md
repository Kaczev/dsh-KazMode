# Kaz 模式

一个 DeepSeek Harness（dsh）的 agent 预设。装好之后，新建对话时在模式列表里选 **Kaz 模式** 即可。

选它，换来的是一个会安排工作的助手：它自己拆活、决定哪些自己做完、哪些交出去，并始终对你负责。下面是它给你带来的东西。

## 它能给你什么

- **一个负责到底的主代理。** 你只跟它对接。它先把需求拆成可验证的几块，能自己做完的自己做完；适合并行的部分派出去同时做，做完再向你收口。活交出去之后责任还在它身上，不会甩手。
- **需要时现配的帮手。** 主代理可以为某一件事临时定义一个角色去做——告诉它干什么、做到什么算好，然后拿回结果。你不需要自己管理这些角色。
- **一批内置技能，按需自动加载。** 预设自带这些技能，遇到对口的活模型会自己取用，不占用平时的上下文：
  - 写作质量、继承措辞审查：让写出来的文档一次读懂，顺手查掉那些没人说得清为什么留下的句子。
  - 界面设计、图标设计：让做出来的页面和图标看起来是刻意设计的，而不是生成的。
  - 办公文档：要交 Word / Excel / PPT / PDF 时，把文件真正排版好，并确认打开后内容对得上。
  - 验证纪律：说"做完了 / 修好了 / 通过了"之前先拿出证据，说清哪部分没验证，不含糊。
  - 用文件做计划：活一长就跨过了上下文，把计划、证据和进度写下来，换一轮对话也接得上。
  - 仓库定位：接手一个不熟的项目时，先弄清东西在哪、该改哪一层。
- **记忆留得住，而且分两层。** 值得记住的东西会沉淀成记忆：机器和环境级的事实放全局，项目级的放项目，换项目也不串味。记忆由专职的记忆管家统一维护——什么时候该记、记到哪一层、旧条目怎么更新都由它管；主代理和帮手只负责查、不负责写，所以记忆库不会互相打架。
- **长会话不会把上下文聊爆。** 上下文快满时，代理自己挑出中间那段可以压掉的部分压成摘要，最近的对话原样留着。压掉不等于丢掉：那些内容以后照样能检索回来，需要时还能按位置把原文整段读回来。
- **几个代理之间可以互查历史。** 想知道某个帮手当时到底怎么做的，可以翻它自己的记录，而不只是看它交上来的结论。
- **全程是"我们"的口径。** 从系统提示到回复，它说的都是"我们"，而不是一个高高在上的工具在对你说教；协作起来更像跟一个搭档说话。

## 怎么装、怎么升

安装和更新都不在本文展开，交给一份写死了每一步的指引，把提示词发给 DeepSeek 让它照着做即可：

- **全新安装**：读 `ds安装指引.md`，提示词见 `ds安装法的提示词.txt`。
- **已有安装的更新**：读 `ds更新指引.md`，提示词见 `ds更新法的提示词.txt`。

装完、升级完都要重启 dsh，改动才会生效；重启后在新对话里选 **Kaz 模式**。

## 需要什么

- **dsh `0.1.5-rc.2`**，只支持这一个版本。其它版本会被安装程序拦下。
- **Windows + PowerShell**。安装指引和安装程序都是按这个环境写的。
- **推荐思考强度 high 及以上**：low 容易冒出 "let me" 式的思维链，安排工作的效果会打折。
