# Kaz 模式

Kaz 为 DeepSeek Harness（DSH）当前选用的预设叠加工作规则，并附带五个按需加载的技能。启用后，你仍使用原来的标准、PTC 或自定义预设；Kaz 不另建预设，也不添加工具。

当前版本 9.6.2，npm 包名为 `dsh-kazmode`。适配目标从 DSH v0.2.1-rc.3 起；包清单没有声明 DSH 版本约束，仓库测试也不代表已经验证每个后续版本。升级 DSH 后仍需检查插件能否正常加载。

## 安装前：它会影响什么

Kaz 安装在当前 profile，供其中的会话使用。[宿主插件](./kaz/index.js)把工作规则注册在原生 persona 之后、规划策略之前，并注册随包技能；[客户端插件](./kaz/client.js)只在已有界面位置显示启用标记。

原生 persona、模式菜单和预设的工具组合不由 Kaz 改写。Kaz 不指定模型或默认回复语言，不补装预设缺少的技能加载工具。若预设采用完整系统提示词（`complete`），其装配仍由 DSH 决定，Kaz 不强制把自己的规则插进去。同名技能也由 DSH 按作用域选择，不保证选中 Kaz 提供的版本。

这些规则是给模型的工作要求，不是对每次输出的保证。模型、预设、权限与可用工具都会影响实际执行。

## 安装、更新与停用

1. 打开 DSH 插件页，添加 `dsh-kazmode` 并启用。需要固定到本版时，填写 `dsh-kazmode@9.6.2`。
2. 新建会话，选择平时使用的预设，直接提出任务。模式菜单里不需要出现一个单独的 Kaz 选项。
3. 检查界面标记：已绑定会话的新会话界面显示「Kaz 已启用」，已有会话顶部显示「· Kaz」。未绑定会话的空白首页可能没有标记。

更新后按插件管理器返回的提示操作，并在新会话中核验；不能仅凭安装成功就认定已有会话采用了新版。停用时，Kaz 注册的提示词、技能和界面标记会撤销，其他来源的同名技能不会因此被删除。

## 日常使用

无须专用命令。照常描述目标、提供材料，并说明允许改动的范围。Kaz 的[完整工作规则](./kaz/prompt.md)要求模型这样处理任务：

- **决定怎么做之前**，核对目标和现场。缺少事实就先做必要观察；确有取舍才比较方案，路径明确就直接处理。低影响的信息缺口可作合理假设，高影响事项须先查明。
- **区分分析与实施授权**。你只要求分析或计划时，实施对象保持只读；已经授权实施时，尽量在当前轮次完成改动和验证。需要额外授权时直接询问。能从请求和已有上下文确定的事直接处理；几种理解会导向不同结果时，问一个开放问题，问你最在意什么。你想参与决定时，先给出仍可修改的具体方案，等你决定后再实施。
- **用检查确认结果**。动手前确定可观察的完成标准；改动后检查新行为和受影响的已有功能。写入报错、超时或响应丢失时，先回读状态，避免重复执行可能已生效的操作。交付时分清已验证事实、假设和未验证项。
- **沿用项目的组织方式**。按导航查找，再读实际文件；索引和摘要不能代替证据。开发中只补必要的导航，按职责放置文件，保留用户内容，不顺手整理无关目录。

遇到视觉方案、应用界面或网页样式设计，模型在开始视觉设计或前端实现时加载 UI 审美技能；涉及品牌、文件类型或界面图标，或要绘制应用、插件图标时一并加载图标技能。交付视觉方案时提供可直接渲染的 HTML，保留可编辑源文件，并说明模拟边界；你要求纯文字、其他格式或不预览时，按你的要求交付。确认后的视觉与交互要求约束后续实现；变更需先确认并更新原方案，HTML 预览也不替代项目原有技术栈。

遇到成篇写作，模型应在写作阶段加载下面的写作技能。若当前任务有相关 Goal，模型应在结束回复前按 DSH 原生策略核对目标状态，而不是把回复结束当作自动执行已停止。

## 随包技能

插件启用时注册技能目录，相关任务需要时才加载正文，不必再往本地技能目录复制一份。

| 技能 | 用在什么地方 |
| --- | --- |
| [automation-recovery](./kaz/skills/automation-recovery/SKILL.md) | 排查 MCP、桥接服务和桌面自动化故障，先区分请求未发送、无副作用拒绝、结果未知和应用阻塞，再核验业务结果。 |
| [icon-craft](./kaz/skills/icon-craft/SKILL.md) | 规定应用、插件与界面图标怎么构成：身份图标自有底板，主图形、线宽与配色在小尺寸下仍然成立；界面线形图标与真实品牌、文件类型标志只解析不手绘。附带单进程 SVG 解析脚本、预量测索引和深浅底色适配样式。 |
| [ui-taste](./kaz/skills/ui-taste/SKILL.md) | 约束 HTML 视觉方案、应用插件界面与网页的密度分类、中性底色与单强调色克制、层级边框、字号对齐和微交互状态。 |
| [windows-command-reliability](./kaz/skills/windows-command-reliability/SKILL.md) | 编写或排查 Windows 命令，处理 shell 边界、路径引用、编码和文件锁。 |
| [write-like-a-person](./kaz/skills/write-like-a-person/SKILL.md) | 创作或实质性修订文章、演讲、报告、文档及较长 UI 文案；从读者与用途出发，依次起草、修改段落、修改句子并核对交付内容。演讲稿另检查翻页提示、字数和时长。 |

你也可以明确要求使用写作技能。普通聊天、代码排查、工作计划和完成摘要，不会仅因含有自然语言就触发它。技能全文仍在上下文时复用，不必反复加载。

## 没有生效时查哪里

「Kaz 已启用」或「· Kaz」只能说明界面插件已启用，不能证明这次会话加载了全部规则和技能。可按现象检查：

- **没有标记**：先确认当前 profile 中插件是否启用，以及页面是否已有绑定会话；不要只用空白首页判断。
- **有标记，但规则似乎没加载**：检查会话实际系统提示词，确认 Kaz 正文只出现一份；再核对预设是否使用 `complete`。标记和提示词来自不同入口。
- **技能无法加载**：确认预设提供技能加载工具，并检查同名技能的作用域选择。Kaz 注册技能，不改变工具组合。
- **切换预设或更新后行为不同**：在新会话核验提示词和技能，同时确认切换前后的工具组合仍与各自预设一致。

核对注册逻辑可读[宿主入口](./kaz/index.js)，核对文字要求可读[提示词](./kaz/prompt.md)。报告问题时请附 DSH 与 Kaz 版本、所用预设、复现步骤和实际报错，提交到 [Issues](https://github.com/Kaczev/dsh-KazMode/issues)。

## 维护仓库

[项目导航](./INDEX.md)列出实现、测试和维护入口。npm 发布内容来自 [kaz 目录](./kaz/)，版本及资源范围由[包清单](./kaz/package.json)定义。

安装维护依赖后，在仓库根目录运行：

```sh
npm ci
node scripts/sync-readme.mjs
npm run check
npm pack ./kaz --dry-run
```

只编辑根 README；[同步脚本](./scripts/sync-readme.mjs)负责生成包内 README，并将相对链接转换为 GitHub 仓库链接。`npm run check` 检查版本、README 同步状态，并运行提示词、技能、客户端标记及发布资源测试。测试采用模拟宿主，不代替真实 DSH 重载或模型行为验证；`npm pack` 的 `--dry-run` 用于检查打包范围，不会发布。

写作技能的唯一来源是 [Kaczev/write-like-a-person](https://github.com/Kaczev/write-like-a-person)。维护该技能时先改来源仓库，再运行[技能同步脚本](./scripts/sync-skill.mjs)；[来源记录](./kaz/skills/write-like-a-person/SOURCE.json)保存来源提交和内容哈希。不要直接改随包副本。图标技能中的 SVG 解析脚本、索引与样式改编自 MIT 许可的 `Leonxlnx/taste-skill`，上游提交与改编范围记录在[图标来源记录](./kaz/skills/icon-craft/SOURCE.json)。
