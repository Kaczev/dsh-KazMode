# Kaz 模式

Kaz 为 DeepSeek Harness（DSH）添加一套工作规则：先观察再决策，按授权范围完成实施与验证；涉及视觉方案或成篇写作时，再应用相应协议。

当前版本 9.5.0。支持 **DSH v0.2.1-rc.3 及以上版本**，npm 包名为 `dsh-kazmode`。

## Kaz 会改变什么

启用后，你仍然选择原来的标准、PTC 或自定义预设。Kaz 在这些预设之上叠加提示词和技能，不新增一套工具，也不替换原生预设。

[完整提示词](./kaz/prompt.md)约定了具体的工作方式：

- **先观察，再决定怎么做。** 核对用户目标与实际状态；事实不足先补充必要观察，有实质取舍才比较方向，路径明确就直接处理。
- **按授权范围办事。** 只要分析或方案，就保持实施对象只读；已授权实施，就尽量在当前轮次完成改动和验证。需要额外授权时直接请求，不绕路或自行扩大权限。
- **边开发边补导航。** 新增模块、目录，或需要跨文件理解改动时，主动建立或补充最小索引；只记录已经检查过的内容，不为建索引扫描全仓库。只读分析不默认写文件，单文件小修改不强制新建索引。
- **新文件按职责归类。** 沿用现有目录结构；没有合适位置时，在所属范围创建用途明确的目录。功能代码、HTML 设计稿、报告和临时脚本不默认堆在根目录，也不为整理目录擅自搬动无关旧文件。
- **用 HTML 展示拟议画面。** 涉及 UI、布局或美术方案时，用可渲染的 HTML 展示拟议效果，并标明模拟边界；用户要求纯文字、其他格式或不要预览时除外。经用户确认的视觉与交互要求约束后续实现，变更须确认并更新原计划，实际实现仍使用项目原有技术栈。
- **用真实检查验收。** 实施前明确可观察的完成标准，修改后检查改动行为及受影响的已有功能；构建通过不等于行为已验证。交付时区分已验证、未验证和验证失败。
- **失败后先核对状态。** 写入报错、超时或响应丢失不代表操作未生效；先读回或查询状态，再决定是否重试，避免重复删除、追加或付费调用。
- **结束回复前核对目标。** 有相关 Goal 时，按原生策略更新状态；回复结束不等于自动执行停止，也不能把可选审阅或一次检查失败当作阻塞。

这些是给模型的工作指令，实际执行仍受所选模型、预设、权限和可用工具约束。

### 9.5.0 的变化

本版重新组织了提示词，明确决策、授权、验证和条件协议的边界。Kaz 不再规定默认回复语言、旧版的直接回答风格或模型切换偏好；相关行为由当前会话中的其他适用指令决定。

随包移除了 `baseline-isolation` 和 `dsh-plugin-field-guide`，精简了自动化恢复与 Windows 操作技能，写作技能保持不变。插件运行时代码和依赖未变。完整变更见 [9.5.0 发布说明](https://github.com/Kaczev/dsh-KazMode/releases/tag/v9.5.0)。

### 按需技能

Kaz 随包注册下列两个通用技能及下一节的写作技能，共三个；只在相关任务加载正文，无须再安装到本地技能根。

- [automation-recovery](./kaz/skills/automation-recovery/SKILL.md)：自动化分层诊断、恢复分支与业务结果核验。
- [windows-command-reliability](./kaz/skills/windows-command-reliability/SKILL.md)：Windows shell 边界、路径编码与文件锁诊断。

### 写作技能

Kaz 随包提供 [write-like-a-person](./kaz/skills/write-like-a-person/SKILL.md)，用于文章、演讲、文档等文稿创作和实质性修订。技能要求先明确读者和用途，再检查文章结构、句子的主语和指代、事实与推测的区分，以及结尾是否只是在重复正文。

普通聊天、代码排查、工作计划和完成摘要不会仅因包含自然语言就触发技能。进入写作阶段，或用户明确要求应用技能时，才加载全文；指令还在上下文中时不重复加载。

## 安装与使用

1. 在 DSH 桌面端的插件页添加 `dsh-kazmode` 并启用。需要固定当前版本时，输入 `dsh-kazmode@9.5.0`。
2. 新建会话，照常选择标准、PTC 或其他预设，无须寻找额外的 Kaz 预设。
3. 已绑定会话的新会话界面会显示「Kaz 已启用」，已有会话顶部会显示「· Kaz」。未绑定会话的空白首页可能不显示标记。

本地开发可安装 [kaz 包目录](./kaz/)。更新或重新安装后，按插件管理器的返回结果操作：`restart-required` 表示需要重启；遇到 `ambiguous-install`，先卸载再安装。不要假定所有已有会话都会立即采用新版本。

**从 9.0.1 及更早版本迁移：** 先把默认预设及需要继续使用的旧会话切换到原生标准、PTC 或其他保留预设，再卸载旧 Kaz、安装新版。新版不再注册 `kaz`、`kaz-ptc`，也不自动迁移依赖这些 ID 的旧会话。

## 生效范围

Kaz 是当前 profile 的全局叠加插件。[宿主入口](./kaz/index.js)将偏好放在原生 persona 之后、规划策略之前，并注册三个随包技能；[浏览器入口](./kaz/client.js)添加启用标记。原生 persona、模式菜单和预设的工具组合保持不变。

- 使用完整系统提示词（`complete`）的预设按 DSH 自身的装配规则处理，Kaz 不强行插入偏好。
- 技能注册不等于增加技能工具：预设没有技能加载工具时，Kaz 不会代为补装。同名技能的优先级遵循 DSH 的作用域规则。
- 禁用后，Kaz 注册的提示词、技能和界面标记会撤销；若其他来源也提供同名技能，该技能仍可能可见。

检查是否正常生效时，除了看界面标记，还应确认系统提示词中只有一份 Kaz 正文、写作技能可以加载、切换预设后的工具组合没有变化。

## 维护

发布内容位于 [kaz 包目录](./kaz/)，版本与资源清单以[包清单](./kaz/package.json)为准，[装配补丁](./kaz/cordis.patch.yml)只负责挂载一个叠加插件。

修改根 README 后，用同步脚本更新 npm 包内的文档；脚本会把仓库相对链接转为 GitHub 链接。在仓库根目录运行：

```sh
npm ci
node scripts/sync-readme.mjs
npm run check
npm pack ./kaz --dry-run
```

检查覆盖版本一致性、README 同步、提示词和技能的注册与撤销、浏览器标记及发布资源。单元测试使用模拟宿主，实际桌面端的显示和会话加载仍需在 DSH 中确认。

写作技能来自独立仓库 [Kaczev/write-like-a-person](https://github.com/Kaczev/write-like-a-person)。修改技能源后再同步，不直接编辑随包副本：

```sh
node scripts/sync-skill.mjs
node scripts/sync-skill.mjs --verify
```

[技能同步脚本](./scripts/sync-skill.mjs)默认读取同级的技能仓库，也支持 `--from <路径>` 或 `WLAP_REPO`。[来源记录](./kaz/skills/write-like-a-person/SOURCE.json)保存来源提交和内容哈希。
